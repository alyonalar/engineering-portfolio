# Checklist: Telegram quiz bot

Цель проверки — пройти основной пользовательский путь и убедиться, что бот предсказуемо обрабатывает некорректные действия. Checklist не заменяет test run: перед выполнением нужно указать версию сборки, дату и окружение.

## Start and navigation

- [ ] `NAV-01` Команда `/start` открывает главное меню.
- [ ] `NAV-02` Повторный `/start` не создаёт дублирующиеся сообщения.
- [ ] `NAV-03` Повторный `/start` во время квиза завершает или сохраняет сессию согласно требованиям.
- [ ] `NAV-04` Команда `/help` показывает доступные действия.
- [ ] `NAV-05` Из каждого вложенного сценария можно вернуться в главное меню.
- [ ] `NAV-06` Неизвестная команда не меняет текущее состояние пользователя.

## File upload

- [ ] `FILE-01` Валидный `.docx` с одним вопросом принимается.
- [ ] `FILE-02` Валидный `.docx` с несколькими вопросами принимается.
- [ ] `FILE-03` Пустой `.docx` отклоняется с объяснением причины.
- [ ] `FILE-04` `.docx` с нарушенной структурой отклоняется до записи вопросов в базу.
- [ ] `FILE-05` Файл другого формата отклоняется до этапа парсинга.
- [ ] `FILE-06` Файл, отправленный вне сценария загрузки, не запускает обработку.
- [ ] `FILE-07` Повторная загрузка не дублирует ранее сохранённые вопросы.
- [ ] `FILE-08` Имя файла с пробелами и кириллицей обрабатывается корректно.
- [ ] `FILE-09` После ошибки бот сообщает, какое действие доступно следующим.

## Quiz flow

- [ ] `QUIZ-01` Квиз можно начать после успешной загрузки вопросов.
- [ ] `QUIZ-02` Количество доступных вопросов совпадает с количеством сохранённых.
- [ ] `QUIZ-03` Вопрос и все варианты ответа отображаются полностью.
- [ ] `QUIZ-04` Правильный ответ увеличивает счётчик правильных ответов.
- [ ] `QUIZ-05` Неправильный ответ увеличивает счётчик ошибок.
- [ ] `QUIZ-06` Повторное нажатие одной inline-кнопки не учитывает ответ дважды.
- [ ] `QUIZ-07` Неправильно отвеченный вопрос возвращается в очередь согласно логике квиза.
- [ ] `QUIZ-08` Ручная остановка завершает активную сессию.
- [ ] `QUIZ-09` После завершения показаны итоговые значения `solved`, `correct` и `wrong`.
- [ ] `QUIZ-10` После завершения старые inline-кнопки не изменяют результат.

## Failure handling

- [ ] `ERR-01` Некорректный ввод не приводит к необработанному исключению.
- [ ] `ERR-02` После ошибки пользователь остаётся на понятном шаге сценария.
- [ ] `ERR-03` Временный сетевой сбой Telegram не повреждает данные активной сессии.
- [ ] `ERR-04` Ошибка загрузки файла не создаёт частично заполненную запись в базе.
- [ ] `ERR-05` В логах ошибки достаточно контекста для диагностики, но нет содержимого пользовательского документа.

## UX and text

- [ ] `UX-01` Названия кнопок описывают результат действия.
- [ ] `UX-02` Сообщение об ошибке содержит причину и следующий шаг.
- [ ] `UX-03` Длинный вопрос визуально отделён от вариантов ответа.
- [ ] `UX-04` Бот не отправляет дублирующиеся уведомления.
- [ ] `UX-05` Формулировки одинаковы в Telegram Desktop и Android.
