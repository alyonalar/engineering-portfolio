# API-тестирование в Postman

Коллекция проверяет связанный сценарий работы с ресурсом `posts` публичного [JSONPlaceholder API](https://jsonplaceholder.typicode.com). Запросы выполняются последовательно: первый шаг выбирает запись и сохраняет её `id`, следующие шаги используют этот идентификатор для чтения, частичного обновления и удаления.

## Покрытие

| Шаг | Проверки |
| --- | --- |
| `GET /posts?userId=:userId` | код `200`, JSON `Content-Type`, применение фильтра, обязательные поля, типы и уникальность `id` |
| `GET /posts/:id` | связь с результатом предыдущего шага, соответствие `id` и `userId`, непустые `title` и `body` |
| `POST /posts` | код `201`, сохранение отправленных значений, назначение числового `id` |
| `PATCH /posts/:id` | изменение только заголовка, сохранение идентификатора и остальных полей |
| `DELETE /posts/:id` | код `200` и ожидаемое пустое JSON-тело |
| `GET /posts/999999` | код `404` и пустой JSON-объект для отсутствующей записи |

JSONPlaceholder имитирует операции записи: ответы на `POST`, `PATCH` и `DELETE` соответствуют контракту, но данные фактически не изменяются на сервере. Поэтому коллекция проверяет контракт каждого ответа, а не последующее сохранение изменений.

## Запуск в Postman

1. Импортировать `postman_collection.json`.
2. Открыть коллекцию `JSONPlaceholder Posts Regression`.
3. Запустить её через **Run collection**.

`base_url`, тестовые данные и рабочие идентификаторы находятся в переменных коллекции. Дополнительное окружение не требуется.

## Запуск из командной строки

При установленном Node.js:

```bash
npx --yes newman@6.2.1 run qa/api-testing/postman_collection.json
```

Та же команда выполняется в GitHub Actions при изменении коллекции или workflow.
